# Rune（符文）

> **刻在你手机里的智能体。**
> 一个完全在 iPhone / iPad 本地运行的通用 Agent —— 不是"遥控器"，不是"云端执行器的前端"。

---

## 0. 一句话定位

**Rune 把 Codex 的沙箱与工程纪律、Claude Code 的工具循环与可扩展性、DSH 的目标/工作流/记忆体系，全部塞进一部 iPhone，让 Agent 的大脑可以调用世界上任何一个模型，而它的手、眼睛、记忆和工作台 100% 在你口袋里。**

三条铁律：

| # | 铁律 | 含义 |
|---|---|---|
| 1 | **端侧执行，绝不远端执行** | 工具循环、文件读写、代码解释执行、Git、检索、记忆、检查点全部在本机进程内完成。没有任何"把命令发到我们服务器执行"的路径。 |
| 2 | **模型可插拔，包括中转站** | OpenAI / Anthropic / Gemini / DeepSeek 为主要一等公民，同时支持全部 OpenAI 兼容渠道、局域网推理、以及第三方中转站（自定义 Base URL + 自定义 Header）。 |
| 3 | **移动不是缩水，是另一种形态** | 体验目标不是"手机上也能用"，而是"手机上更好用"：语音驱动、单指审阅、锁屏续跑、Live Activity 常驻、一键回滚。 |

## 3. 四条必须记住的设计决策

1. **原生优先，沙箱兜底：能原生就原生，必须跑任意代码才进沙箱。**
   iOS 不允许 `fork`/`exec`（`Process` 只在 macOS 可用），也**不存在通用 JIT 权限**。因此 Rune 的工作台是分层的：
   - **高频操作全部原生 Swift 实现**（读写、glob、grep、Git、diff/patch、图像、表格、HTTP）——微秒到毫秒级，覆盖约 90% 需求；
   - **只有"必须执行任意代码"时才进执行环境**：**原生 CPython**（XCFramework + 自研 no-fork 垫片，Pyto/a-Shell 同款路线）、**自研 shell 解释器**（命令表映射到原生实现，无 fork/exec）、**WasmKit 沙箱**（跑用户/模型产出的 `.wasm`）、**JSC/quickjs-ng**（工作流与纯 JS）；
   - ⚠️ **不用 CPython-wasm**：官方 WASI 构建是实验状态、约 150MB、**不支持线程/子进程/socket** —— 这条路已核实为死路；
   - VFS 把 `/workspace` 映射到真实的 iOS 容器目录，含用户通过文件选择器**显式授权**的外部目录（security-scoped bookmark），所有写入都进**写时复制快照**，可秒级回滚。
   **这既是唯一可行的路，也是一条更好的路**：天然可审计、可限流、可回滚、可快照。
2. **"跑得久"靠 `BGContinuedProcessingTask`（iOS 26+），不靠"常驻后台"。**
   iOS 只有几类后台原语：`BGAppRefreshTask` **最多 30 秒**、静默推送 **30 秒且每小时最多 2-3 条且不保证送达**、`BGProcessingTask` 只在设备空闲时跑且用户一用设备就被终止。
   真正能用的是 **`BGContinuedProcessingTask`**：由用户在**前台发起**、可在后台继续**"数分钟或更久"**、允许联网与密集 CPU、进度以**系统 Live Activity** 展示、**用户可随时取消**。
   在此之上，Rune 用 **Turn 级检查点 + 事件溯源** 保证"随时被杀都能接上"：每一步工具调用都遵循"先记意图 → 执行 → 再记事实"的三步落盘协议，进程被回收后从最后一个 checkpoint 重放，幂等工具安全重做，非幂等操作必须询问用户。**用户感知是"它一直在"，实现上是"它总能接上"。**
3. **能力（Capability）比权限更像安全模型。**
   每个工具调用携带一枚范围受限的能力令牌（路径前缀、出口域名、时长、调用次数、是否需 Face ID）。文件里读到的内容一律标记为**不可信内容**，永不自动升级为指令——这是对抗提示注入的唯一结构性办法，不是靠 prompt 里写"请勿执行恶意指令"。
4. **端侧不是"小号云端"，而是神经系统。**
   Apple Foundation Models 的端侧会话窗口只有 **4096 token**（含指令与工具 schema，Apple 建议工具数 ≤ 3-5），**装不下一个自由 Agent 循环**。所以端侧只跑"神经反射"（分类、摘要、脱敏、内容过滤、分支决策）；离线时的主力形态是 **L2 引导模式**——由**确定性运行时**执行声明式配方，只在分支点让端侧模型做一个三选一。**这是"手机上离线可用"唯一诚实且可行的形态。**

## 6. 三条必须提前接受的硬代价

设计文档不是许愿池。这三条是核实之后**确认无法绕过**的代价，写在这里以免后来者以为可以"优化掉"：

| 代价 | 事实 | 为什么绕不过 |
|---|---|---|
| **App 体积 1-2GB** | 实测同类 App：Pyto 930MB、Pythonista 853MB、**a-Shell 1950MB** | 内嵌 CPython 的必然结果；且因 2.5.2 **运行时必须随包，不能"首次启动下载"** |
| **没有后台常驻** | `BGAppRefreshTask` 最多 30 秒；静默推送每小时 2-3 条且不保证送达；锁屏后 SSE 必断 | iOS 不会给任何 App 这个能力。我们只能用 `BGContinuedProcessingTask` + 检查点续跑把体验"拼"出来 |
| **端侧模型能力有限** | Apple FM 端侧窗口 **4096 token**（中文约 2-3 千字）、建议工具数 ≤ 3-5；6GB 设备实测可用内存约 **3.1GB** | 端侧只能做"神经反射"；离线主力形态是**确定性运行时 + 端侧分支决策**（L2 引导模式） |

**把代价说清楚，比假装没有代价更值得信任**——这条原则贯穿整个文档集。

## 7. 命名说明

主名 **Rune**（中文名 **符文**，读作"鲁恩"）。选择理由：rune 是"刻在载体上、承载力量的最小符号"——恰好是 Agent 的工作单元（一次工具调用、一段 diff、一条记忆）；四字母、双音节、中英文均可读；不与主流 Agent 产品重名。

备选（已评估、未采用，理由见 [01](docs/01-产品定义与愿景.md#附录命名决策记录)）：Kiln、Hearth、Nabu、Flint、Lathe。
