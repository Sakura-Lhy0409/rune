# 19 · 真实运行时接线与验收（C45）

本轮把 C42 的界面接到实际运行时。它是 **0.2.0 运行时预览版**，不是整个路线图已经完成的正式版本。

## 1. 现在实际经过的链路

```text
用户在会话里确认开始
  → 读取所选渠道与 Keychain 凭据
  → 持有工作区 security-scoped bookmark
  → RuneCore.AgentRuntime（独立串行队列）
      → 先提交模型调用意图
      → RequestBuilder 出站历史检查
      → ModelClient 路由/重试/完整结果缓存
      → URLSession + 原生 SSE 流式预览
      → TurnRunner.step
          只读工具 → VFS / PDFKit / Vision / CSV 解析
          修改工具 → 审批 + 差异预览 → 先提交工具意图 → 执行 → 提交结果
      → RuneStore 同一 SQLite 事务保存新事件 + 完整状态 + 审批元数据
  → UI 投影 / 实时活动 / 系统后台任务进度
```

生产网络传输已接入。新增 UI 测试用脚本化 HTTP 响应替代云端推理，其他层全部真实执行；另有 Core 测试在真实 loopback TCP 服务上跑 URLSession、审批、文件写入和数据库验链。**这些通过不等于云端模型推理验收通过。**

## 2. 本轮交付

| 部分 | 实现与边界 |
|---|---|
| RuneStore v2 | 新增 runtime_checkpoint；revision 乐观锁；事件与状态一笔事务；提交失败不推进下一个副作用；v1 原位迁移 |
| 恢复 | 校验检查点散列与事件链尾；识别网络调用中途退出；未知非幂等操作重新交给用户；不会自动在冷启动时烧钱 |
| 文件修改 | 18 个实际可用工具中的修改类强制逐次审批；审批期间文件改变则拒绝覆盖；执行前再次比对；已成为目标内容时跳过重复写入 |
| 撤销 | 用户发起，检查当前文件仍等于修改后内容；先写撤销意图再操作，再记事实；新建文件撤销会删除文件而非留空文件 |
| 取消 | 线程安全控制器唤醒重试等待并取消在途请求；稳定审批态也能取消；状态落盘后重开不自动续跑 |
| 流式显示 | 网络线程解析 SSE，节流回调到 UI；流式文字只是预览，完整轮次结束后才形成可执行工具调用 |
| 出口记录 | 域名、方法、阶段、字节数与状态码写入事件链；日志不存鉴权头、查询字符串或请求正文 |
| 成本 | 用户填写渠道报价；整数微美元记账；每轮预留历史/schema/输出及重试预算；不足时先暂停。无报价明确显示未知，限轮次和工具数；渠道账单为准 |
| 同步桥接 | ModelClient 与 TurnRunner 保留已测同步接口，仅在专用工作队列运行；UI 通过 AsyncThrowingStream 接收结果 |
| 文件隔离 | 模型视图屏蔽凭据、.git/.rune/.ssh、策略/审计区域；过滤 list/grep/copy；检查解析后的真实路径，防止内部符号链接指向 .env |
| 文档 | PDFKit 提取文字层与页号；Vision 本机 OCR；UTF-8 CSV/TSV 解析引号、逗号、换行。没有宣称 Excel/Word/PPT 解析已实现 |
| 附件 | 用户选择的附件从 Inbox 复制到授权工作区 attachments，真实路径进入任务；图片可由 OCR 读取文字 |
| 后台 | iOS 26+ 尝试 BGContinuedProcessingTask；无法分配则用有限的 UIApplication 后台时间；到期请求暂停。不是后台常驻，真机长时验收仍未完成 |
| 渠道 | 自定义模型、协议、Keychain、模型列表连接测试；显式局域网选项。HTTP 仅由传输层允许本地地址，仍受系统 ATS/权限约束 |

## 3. 修掉的接线缺陷

1. ModelClient 以前命中去重时返回空事件，UI 无法得到答案。现在缓存完整事件并重放；重放去掉 usage，避免重复计费。
2. HTTP 200 内的模型错误帧以前仍可能被记为成功；现在在记录健康/缓存前检查解码错误。
3. 文件工具的默认注册策略有些是 `never`。Core 的实际工具表把修改类统一提升到 `always`，没有只依赖按钮说明。
4. 原 App 用 UI JSON 充当全部状态。生产运行状态现在在 RuneStore；UI JSON 是可重建投影。
5. 缺省费用 0 曾让未报价渠道看起来免费。界面现在区分未知和估算，预算与报价随任务保存，不因后来设置变化静默改写。
6. 无法预览的大文件不能直接继续写；保持可拒绝的审批并禁用批准，用户能让模型缩小范围。
7. 打包脚本复用现有 zip 会保留上个版本已删除的条目。现在创建全新临时归档后替换正式 IPA，并递归移除主 App 和扩展的旧签名。

### 真实中转站结果：尚未通过

使用用户已配置的 PinAI Key，只发送合成目录中的 `before`/`after` 测试文本，未发送项目源码或真实个人文件。模型列表列出的 `gpt-5.4-mini`、`gpt-5.4`、`gpt-5.2` 实际均被上游拒绝，信息为：

> The model is not supported when using Codex with a ChatGPT account.

因此不再盲试其他型号；需要中转站确认**实际可调用的文本模型与对应协议/账户线路**。图片模型此前成功不代表文字模型也已可用。此项不可记为云端端到端成功。

合成验收程序在 `Packages/RuneCore/Sources/RuneValidation/main.swift`。它仅在进程环境提供 `RUNE_LIVE_API_KEY` 时调用网络，模型/Base URL 分别由 `RUNE_LIVE_MODEL` / `RUNE_LIVE_BASE_URL` 指定，不把密钥硬编码到 App。
