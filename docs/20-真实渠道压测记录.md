## DeepSeek 官方渠道的实测事实

| 项 | 实测值 |
|---|---|
| Base URL | `https://api.deepseek.com` |
| 鉴权 | `Authorization: Bearer <key>` |
| 协议族 | OpenAI Chat Completions 兼容（`/chat/completions`） |
| `GET /models` 返回 | `deepseek-flash` · `deepseek-v4-pro` |
| 工具调用 | ✅ 两个模型都返回 `finish_reason: "tool_calls"` 与结构化 `tool_calls` |
| 计费字段 | `usage` 含 `prompt_tokens` / `completion_tokens` / `total_tokens`；缓存**两种形状都给**：嵌套 `prompt_tokens_details.cached_tokens` **与**扁平 `prompt_cache_hit_tokens` / `prompt_cache_miss_tokens` |
| 缓存计费 | ✅ **实测命中**（同一前缀连打两次）：第 1 次 `cached_tokens=0`、第 2 次 **`cached_tokens=384`**，且与扁平字段一致。⚠️ 关键在于**嵌套字段确实会被填充** —— 若只填扁平字段，我们的解码器（读 `prompt_tokens_details.cached_tokens`）就会静默按 0 记账 |
| 流式 | ✅ `/chat/completions` 支持 `stream` + `stream_options.include_usage`，最后一帧带**同样形状**的 `usage` |

⚠️ **`deepseek-chat` 是别名，会解析到 `deepseek-flash`**
（实测：请求 `deepseek-chat`，响应体里的 `model` 字段是 `deepseek-flash`）。

这对"模型可插拔"有一个直接影响：**用户在配置里填的名字，与模型自报的名字可能不同**。
`modelSelected` 事件记的是**解码器从响应里读到的那个**（即真实执行者），
所以审计里会出现 `deepseek-flash` —— 这是**对的**（审计该记事实，不该记用户的输入），
但 UI 上若把两者并排显示，需要说明"你配的是 A、实际跑的是 B"。

⚠️ 缓存字段的结论（**实测，不是推测**）：DeepSeek 同时给嵌套与扁平两种形状，
且命中时**嵌套那个也会被填**（384）。所以现有的 OpenAI 风格解码
（读 `prompt_tokens_details.cached_tokens`）**是对的**，命中会被正确记进 `cacheInfo`。
—— 这一条值得留痕，因为它本来是"看起来像 bug"的：只扫字段名会以为我们读错了字段。
