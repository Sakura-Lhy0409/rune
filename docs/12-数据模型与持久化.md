# 12 · 数据模型与持久化

> **摘要**：Rune 的持久化只有一条主线——**事件日志（event log）是唯一真相源**，其余一切都是它的投影或缓存。会话、检查点、记忆、审计、成本账本全部可**从事件重建**。这个选择一次性解决了四件难事：断点续跑、时间轴回滚、审计溯源、崩溃恢复。

---

## 1. 选型

| 需求 | 选择 | 理由 |
|---|---|---|
| 主存储 | **SQLite + GRDB 7.x** | 需要事务、FTS5、向量检索、精细索引与可控迁移；单文件、零运维、WAL 并发读。**GRDB 7.0 已全面 Swift 6**，是当前唯一成熟选择 |
| 全文检索 | **FTS5** —— ⚠️ **但绝不能用 `unicode61`** | `unicode61` **会静默丢弃 CJK 字符**，中文项目检索会返回零结果且不报错。必须按语料选择 **CJK 分词器** 或 **`trigram`**，代码走自研分词（驼峰/下划线切分）。详见 [07 §4.1](07-上下文与记忆引擎.md) |
| 向量检索 | **sqlite-vec**（自研兜底） | ⚠️ 仍是 **0.1.x**（曾长期停更，现恢复维护），**ANN(DiskANN) 尚未完成** → 当前实际是线性扫描，≤5 万向量可用。⚠️ **iOS 默认禁用 loadable extension，必须把 C 源码编进 App 并静态注册**。备选：USearch（SwiftPM 可用）、hnswlib.swift、Accelerate 的 `BNNS.NearestNeighbors` |
| 大对象 | **文件系统 + 元数据表** | 二进制（图片/日志/产物）不进数据库，避免库体积爆炸与备份代价 |
| 敏感字段加密 | **SQLCipher 或字段级 AES-GCM** | 可选开启；默认用字段级（对性能影响小、可精确定位敏感字段） |
| 缓存 | 内存 LRU（NSCache/自研） | 不持久化，进程退出即失 |

**不选 SwiftData/Core Data 的原因**：**SwiftData 目前仍是"仅实验"级**（大表内存增长、关系迁移崩溃等公开问题），且**没有 FTS**，而我们恰恰需要 FTS5 + 向量 + 精细迁移控制。Agent 的存储层还必须能被工程师直接拿 `sqlite3` 打开检查——这一点 SwiftData 完全做不到。

```sql
CREATE TABLE session (

CREATE TABLE turn (

  input_preview     TEXT NOT NULL,               -- 用户输入的截断预览（列表显示用）
  plan_json         TEXT,
  plan_approved_at  INTEGER,
  trust_level       TEXT NOT NULL,
  model_used        TEXT,
  provider_used     TEXT,
  degraded_from     TEXT,                        -- 若发生降级，记录原模型
  cost_micro_usd    INTEGER NOT NULL DEFAULT 0,  -- 微美元整数，避免浮点误差

  tokens_out        INTEGER NOT NULL DEFAULT 0,

  started_at        INTEGER NOT NULL,

```

**`cost_micro_usd` 用整数**：浮点累加会漂移，用户对账单很敏感。

### 2.3 事件日志（唯一真相源）

```sql
CREATE TABLE event (
  -- ⚠️ 序号是**按会话**算的，不是全局单调：`EventLog` 每个会话一个实例，
  --    两个会话各有一条 seq = 1，因此主键必须是 (session_id, seq)。
  --    （原稿写的是 `seq INTEGER PRIMARY KEY AUTOINCREMENT` 且注释「全局单调」，
  --      与内核实现矛盾 —— 单列主键会让「开第二个会话」直接撞 UNIQUE 约束；
  --      由 RuneStore 的 chainsArePerSession 测试当场抓到，见 PROJECT_STATE §4.2。）
  session_id        TEXT NOT NULL REFERENCES session(id) ON DELETE CASCADE,
  seq               INTEGER NOT NULL,                     -- 会话内单调，从 1 开始
  id                TEXT NOT NULL UNIQUE,                 -- UUID
  turn_id           TEXT REFERENCES turn(id) ON DELETE CASCADE,
  goal_id           TEXT REFERENCES goal(id) ON DELETE SET NULL,
  subagent_id       TEXT,                                 -- 子代理泳道
  kind              TEXT NOT NULL,                        -- 见下方枚举
  payload_json      TEXT NOT NULL,                        -- 事件体（大内容走 payload_ref）
  payload_ref       TEXT,                                 -- 若内容在制品文件里
  origin_trust      TEXT NOT NULL,                        -- 该事件内容来源信任级
  tainted           INTEGER NOT NULL DEFAULT 0,           -- 污点标记（传播用）
  created_at        INTEGER NOT NULL,
  prev_hash         BLOB,                                 -- 哈希链
  hash              BLOB NOT NULL,
  PRIMARY KEY (session_id, seq)
);
CREATE INDEX idx_event_session ON event(session_id, seq);
CREATE INDEX idx_event_turn ON event(turn_id, seq);
CREATE INDEX idx_event_kind_time ON event(kind, created_at DESC);
```

**事件类型枚举（节选，共约 40 种）**

| 分组 | kind |
|---|---|
| 会话 | `SessionCreated` `SessionTitleSet` `SessionArchived` `MemoryDisabled` |
| 输入 | `UserMessage` `VoiceTranscribed` `ShareReceived` `IntentInvoked` `CameraCaptured` |
| 计划 | `PlanProposed` `PlanApproved` `PlanRevised` `PlanStepStatusChanged` |
| 模型 | `ModelCallStarted` `ModelCallStreaming`（仅计数，不存全文）`ModelCallFinished` `ModelCallFailed` `ModelDegraded` `ReasoningBlockReceived` |
| 工具 | `ToolCallRequested` `ToolApprovalRequested` `ToolApprovalDecided` `ToolCallStarted` `ToolCallFinished` `ToolCallFailed` `ToolCallDenied` |
| 沙箱 | `SandboxStarted` `SandboxResourceWarning` `SandboxKilled` `SandboxOutputChunk` |
| 文件 | `FileRead` `FileWritten` `FileDeleted` `FileMoved` `PatchApplied` `PatchRejected` |
| Git | `GitCommit` `GitPushAttempted` `GitPushSucceeded` `GitPushFailed` `PRCreated` |
| 检查点 | `CheckpointCreated` `CheckpointRestored` `TurnForked` |
| 安全 | `CapabilityRequested` `CapabilityGranted` `CapabilityDenied` `EgressBlocked` `InjectionSuspected` `HumanOnlyZoneTouched` |
| 预算 | `BudgetWarning` `BudgetExceeded` `TurnPaused` `TurnResumed` |
| 生命周期 | `AppForeground` `AppBackground` `TurnInterrupted` `TurnRecovered` `OfflineDetected` `LowPowerEntered` `ThermalPressure` |
| 编排 | `SubagentSpawned` `SubagentFinished` `WorkflowPhaseStarted` `WorkflowFinished` `JobStarted` `JobFinished` `JobKilled` |
| 记忆 | `MemoryCandidateCreated` `MemoryWritten` `MemoryRejected` `MemoryQuarantined` |
| 交付 | `ArtifactCreated` `FileReturned` `NotificationSent` |

**哈希链**：`hash = SHA256(prev_hash || id || kind || payload_hash || created_at)`。用于检测篡改（T11）。每 1000 条做一次锚点（`anchor` 表存 seq + hash），校验时只验锚点 + 尾部。

## 3. 索引与性能

| 查询场景 | 索引/手段 | 目标 |
|---|---|---|
| 会话列表（按工作区分组、最近优先） | `idx_session_ws_time` | < 5ms |
| 打开会话 → 加载最近 N 轮事件 | `idx_event_session` + 分页（seq 倒序，每次 200 条） | < 15ms |
| 恢复扫描（未完成 Turn/Job/Goal） | `idx_turn_open`（部分索引）+ `idx_job_open` | < 3ms |
| 全文检索历史 | FTS5 影子表（`event_fts` 仅索引 UserMessage / 工具摘要 / 助手结论） | < 50ms |
| 向量检索 | sqlite-vec 线性扫描（≤ 5 万条，384 维）≈ 15ms；超过则分片量化 | < 60ms |
| 成本统计 | `idx_cost_time` + 物化到 `session.stats_json` | < 5ms |
| 事件写入 | 单写者 actor + 批量提交（每 20 条或 50ms 一次事务） | ≥ 5k 事件/s |

**写放大控制**：事件表是热表，长期运行会到数十万行。策略：
- 大 payload 一律外置到制品文件（`payload_ref`），表里只留摘要
- 90 天前的事件迁移到"归档库"（`archive.sqlite`，同目录），主库只留索引与哈希锚点
- 用户可设"保留 N 天后自动清理原始事件"（默认永不清理，因为可重建是核心价值）

## 4. 迁移策略

```swift
// GRDB DatabaseMigrator：只前进，不后退；每步必须可在 3 秒内完成（移动端不能卡启动）
var migrator = DatabaseMigrator()
migrator.registerMigration("v1_initial") { db in ... }
migrator.registerMigration("v2_add_taint_column") { db in
    try db.alter(table: "event") { t in t.add(column: "tainted", .integer).notNull().defaults(to: 0) }
}
migrator.registerMigration("v3_knowledge_vec_index") { db in ... }

// 规则
// 1. 破坏性变更（删列/改类型）必须走"建新表 → 拷数据 → 换名"，绝不 ALTER 原地改
// 2. 大表加索引走"后台迁移 + 断点续做"（记录 progress 表）
// 3. 每次迁移前自动生成一份轻量备份（schema + 最近 1000 条事件），失败可回滚
// 4. 迁移在 App 启动的"预启动阶段"执行，UI 显示进度（不阻塞首页渲染）
```

**版本门禁**：若数据库 schema 版本**高于**当前 App（用户装了旧版 App 但数据库是新版的降级场景），**拒绝打开并提示**（不要尝试降级解析），避免数据损坏。

## 5. 崩溃恢复流程

```
启动
 ├─ 1. 打开数据库（WAL 自动恢复）
 ├─ 2. 校验哈希链尾部（最近 1 个锚点 + 之后全部）
 │     └─ 不一致 → 停止自动续跑，提示用户"历史记录校验未通过"，提供"重建索引/导出原始数据"选项
 ├─ 3. 扫描未完成实体：turn(state ∉ 终态) / job(state ∈ {queued,running,resumable}) / workflow_run(未完成)
 ├─ 4. 分诊：
 │      · 有活跃 Goal → 恢复计划
 │      · Turn 处于"可安全重做"状态 → 从最后检查点重放（幂等规则见 04 §1.2）
 │      · Turn 含不可重放副作用（推送/外发）→ 标记为"需要用户确认后继续"
 │      · 超过 24 小时的僵尸实体 → 标记为 interrupted，不自动续跑（避免"半夜自己跑起来"）
 ├─ 5. 清理临时状态：删除 tmp/ 下未提交的事务、清理孤儿快照
 └─ 6. 恢复 UI：首页显示"已从检查点恢复"（可展开细节）
```

**"超过 24 小时不自动续跑"是一条重要产品决策**：用户不希望三天前一个忘了的任务突然开始跑并花钱。

## 6. 备份、同步与迁移

| 能力 | 设计 |
|---|---|
| **iCloud 备份** | 数据库默认**包含**（用户可关）；制品与索引默认**排除**（`isExcludedFromBackup`）；密钥永不备份 |
| **导出** | 会话/记忆/审计导出为 JSON + Markdown 包（人类可读），可导入到另一台设备 |
| **设备间同步（可选，P2)** | 不用我们的服务器：iCloud 私有库（CloudKit）或用户自建 WebDAV；端到端加密（密钥由用户设备间通过 iCloud Keychain 同步） |
| **冲突处理** | 事件日志天然可合并（追加式），冲突只在"同一文件的并发写入"，按检查点时间戳 + 人工确认解决 |
| **加密同步范围** | 会话、记忆、策略可选同步；工作区文件不通过 Rune 同步（那是 Git 的事） |

**不同步的理由（默认关闭）**：Rune 的核心卖点是"数据不离开设备"。同步是可选增强，且必须走用户自己的云。

## 7. 数据生命周期与用户控制

| 数据 | 默认保留 | 用户可调 | 自动清理 |
|---|---|---|---|
| 会话与事件 | 永久 | 可设"90 天后清理" | 否（除非用户开启） |
| 制品 | 永久 | 可设 30/90 天 | 是（按 `expires_at`） |
| 索引（L1/L2） | 永久 | — | 是（commit 变更时增量替换） |
| 出口审计 | 永久 | 可设"1 年后归档" | 否 |
| 安全事件 | 永久 | — | 否（安全记录不应自动消失） |
| 模型请求/响应存档（Debug） | 7 天 | 可关 | 是 |
| tmp | 会话结束 | — | 是 |

**"一键清空"**：设置页提供三级
1. 清会话（保留记忆与工作区）
2. 清记忆 + 会话
3. **完全重置**（清数据库 + 制品 + 索引 + 删除全部凭据 + 撤销工作区授权）→ 需 Face ID + 手输 `RESET`

## 8. 数据库健康与自维护

| 任务 | 时机 | 动作 |
|---|---|---|
| WAL 检查点 | 每 500 次写入或每次后台切换 | `PRAGMA wal_checkpoint(TRUNCATE)` |
| 空间回收 | 每周 BGProcessingTask | 删除 > 20% 空闲页时 `VACUUM`（在充电 + 后台） |
| 完整性校验 | 每月 / 崩溃后 | `PRAGMA integrity_check` + 哈希链校验 |
| 索引重建 | 检测到 commit 大变更 | 增量重建 L1/L2 |
| 体积报告 | 设置页 | 各表与制品占用可视化 + 一键清理 |

## 9. 与其他模块的契约

| 契约 | 规定 |
|---|---|
| 写入 | **只有 `EventLog` actor 能写 `event` 表**；其他模块通过事件追加，禁止直写 |
| 读取 | 读操作可并发（WAL + 只读连接池，默认 3 个只读连接） |
| 事务边界 | 一个事件 = 一个事务（批量提交时 ≤ 50ms 窗口）；**跨表原子性只在一个事件的处理内保证**（例如 `CheckpointCreated` 同时写 checkpoint + vfs_snapshot） |
| 幂等键 | 所有写入实体使用 UUID，重复写入按主键冲突忽略（支持重放） |
| 删除 | 一律软删除（`state` 或时间戳字段），物理删除只在用户显式"清空"时发生 |
