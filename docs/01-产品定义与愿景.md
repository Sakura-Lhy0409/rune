# 01 · 产品定义与愿景

> **摘要**：Rune 不是"把 Claude Code 搬到手机上"。桌面 Agent 之所以好用，靠的是三样手机没有的东西——无限的后台时间、完整的 POSIX 进程模型、以及一块可以同时摊开代码/终端/浏览器的屏幕。Rune 的全部设计工作，就是**在不具备这三样东西的前提下，让 Agent 的能力不缩水，同时在手机独有的维度（语音、传感器、常伴、通知、单手）上做到桌面永远做不到的事**。

---

## 1. 问题：桌面 Agent 迁移到手机，会死在哪

先承认现实。把一份成熟的桌面 Agent 代码直接搬到 iOS，会依次撞上五堵墙：

| # | 墙 | 具体表现 | 桌面 Agent 的默认假设 |
|---|---|---|---|
| W1 | **没有进程** | 不能 `fork` / `posix_spawn` / `exec`，不能跑 `bash`、`git`、`rg`、`python` 这些二进制 | "Bash 是一切工具的总入口" |
| W2 | **没有全局文件系统** | App 只能看自己的容器 + 用户显式授权的目录。`/etc`、`/usr/bin`、`~/code` 都不存在 | "工作目录就是用户的项目目录" |
| W3 | **没有后台常驻** | 退到后台 30 秒左右就被挂起，几分钟后被回收。没有 daemon、没有 cron、没有长连接守护 | "Agent 在后台慢慢跑，用户干别的" |
| W4 | **没有随意下载执行** | App Store 禁止下载并执行会改变 App 功能的代码（Guideline 2.5.2），JIT 也受限 | "插件/脚本生态随便装" |
| W5 | **没有宽屏幕** | 5.5 英寸的可视宽度，软键盘吃掉 40% 高度，没有并排窗口 | "Edit-Diff-Review 三栏并排" |

**绝大多数手机 Agent 产品的选择是：把执行搬到云端。** 于是手机上只剩一个聊天框，Agent 的"手"长在别人的服务器上。这带来四个不可接受的问题：

1. **可信度**：Agent 要动的是你的私人数据。上了云，你只能选择"信任"。
2. **延迟与手感**：每一次工具调用都要一个来回，"本地 grep 10 万个文件"变成一次云端排队。
3. **可用性**：断网、地铁、飞机、境外网络不稳 → Agent 直接变砖。
4. **成本结构**：云端执行意味着你必须为"算力"付费，于是被迫卖订阅、加限额、砍能力。

Rune 的立场很明确：**云端只允许做一件事——推理（token 生成）。其余一切在本机。**

## 2. 用户与场景

### 2.1 四类核心用户

| 画像 | 描述 | 最痛的点 | Rune 给他的第一价值 |
|---|---|---|---|
| **A. 移动工程师** | 25-40 岁后端/全栈/客户端工程师，电脑在工位，人在通勤/会议/沙发 | "CI 红了，但我不想开电脑" / "线上告警了，先看一眼" | 手机上完成 triage：读日志、定位、开 PR、改一行热修 |
| **B. 独立开发者 / 创业者** | 一个人干一整条产品线，iOS + 后端 + 数据 | 碎片时间被浪费；灵感来时无法立即开工 | 语音口述需求 → 端侧生成方案与代码 → 手机上直接提交 |
| **C. 数据/运营/研究型知识工作者** | 用 Python/pandas、写 SQL、做报表、爬公开数据 | 脚本运行环境和数据都在电脑上 | 端侧 Python 沙箱 + 文件/表格/图表全流程 |
| **D. 极客 / 隐私敏感者** | 会自己配 API key、用中转站、自建服务 | 讨厌订阅、讨厌数据上云、讨厌被限额 | BYOK + 端侧执行 + 完全离线可用（配局域网/端侧模型） |

四类人的共同点：**他们都有"必须马上处理，但手边没有电脑"的时刻**，并且他们都愿意为"这件事不用等回工位"付出溢价。

### 2.2 场景故事（这些场景直接决定功能优先级）

**S1 · 通勤路上的 CI 抢救（画像 A）**
> 地铁里，Rune 的 Live Activity 弹出一条推送："`main` 分支 CI 失败 · `tests/api/test_orders.py::test_refund`"。
> 用户长按灵动岛 → 弹出三个动作：`诊断` / `忽略` / `在 App 中打开`。点"诊断"。
> Rune 在锁屏状态下用静默推送唤醒 → 拉取失败日志（走用户配置的仓库 token）→ 端侧 `grep`/`rg` 定位 → 调用模型分析 → 生成修复 diff → 检查点落地 → 再次挂起。
> 用户出地铁解锁手机：屏幕上是一张 **诊断卡**："根因：退款金额在币种转换后未四舍五入，浮点比较失败。已生成 3 行修复 + 1 个测试。" 两个按钮：`应用并提交` / `先看代码`。
> 从收到推送到点下"应用并提交"，用户只按了 **3 下**，用时 20 秒。

**S2 · 会议中的白板（画像 B）**
> 用户拍下白板上的数据模型草图 → 分享菜单 → Rune。
> Rune 走端侧 Vision OCR + Apple Foundation Models 做结构化 → 生成 SQL migration + 对应的 Swift model + 单元测试 → 在端侧 Python 沙箱里跑 `pytest` 验证 → 全部通过后把 diff 呈上。
> 用户单手左右滑动逐条 accept/reject，点"提交"。

**S3 · 语音长任务（画像 B/D）**
> 用户戴着耳机走路："Rune，把我 `~/Projects/site` 里所有图片压到 200KB 以下，改完顺便把 README 里的体积说明更新一下，别动 _原图 那个目录。"
> Rune 语音转写 → 生成计划 → 端侧 Python + Pillow（wasm）批量处理 → 中途用户补一句"等等，先备份一份" → **转向（steer）** 正在跑的 Turn，插入备份步骤 → 完成后 Live Activity 显示"压缩 128 张，省 41MB"。

**S4 · 数据日报（画像 C）**
> 用户把 CSV 拖进 Rune 的收件箱文件夹 → 早上打开："按区域汇总上月 GMV，标出环比跌超 10% 的，生成一张图发我。"
> 端侧 Python 沙箱跑 pandas → 生成 PNG → 通过 `return_file` 直接出现在聊天里 → 用户转发给老板。

**S5 · 断网可用（画像 D）**
> 飞机上。Rune 检测到无网络 → 自动切到端侧模型（Apple FM 或 MLX 上的 Qwen3-4B）→ 仍能完成"读文件、改代码、跑测试、写提交信息"的完整闭环，只是复杂推理能力下降，UI 明确标注 `本地模式 · Qwen3-4B`。

**S6 · 隐私洁癖（画像 D）**
> 用户配置了"敏感项目"标记 → 该项目下所有 Turn 强制走"仅端侧模型 + 禁止任何出口请求（除 git 远端）"→ 出口审计页可看到每一次网络请求的域名、目的、携带的字节数。每一次第三方模型调用前，UI 展示"将要发送的内容预览"，并可一键**永久脱敏规则**（如手机号、内网域名、`.env` 值）。

## 3. 产品主张

### 3.1 一句话价值

> **口袋里有一台会自己干活的工程工作站，钥匙和数据都归你。**

### 3.2 与"云端手机 Agent"的差异

| 维度 | 云端执行型手机 Agent | **Rune** |
|---|---|---|
| 执行位置 | 厂商服务器 | 你的手机（WASM 沙箱 + 原生能力） |
| 数据流向 | 你的代码/文件上传到第三方 | 默认只在设备内；只有"发什么给模型"由你控制 |
| 断网 | 完全不可用 | 降级为端侧模型，主干功能仍可用 |
| 延迟 | 每次工具调用一次 RTT | 本地工具零延迟，只有模型推理有网络延迟 |
| 成本 | 必须订阅（含算力） | BYOK：你按 token 付费给模型厂商；Rune 本身可以一次性买断 |
| 扩展性 | 厂商能做多少你就有多少 | 用户/社区可写 Skill、Workflow、MCP Server，纯本地加载 |
| 可审计 | 黑箱 | 每一次工具调用、网络出口、文件写入都有本地事件日志 |

### 3.3 三大支柱能力

**支柱一：端侧工作台（The Bench）**
一台真的能跑东西的工作台，而不是"给模型看看文件"的只读视图。
- 类 Unix 虚拟文件系统，`/workspace` 挂载真实目录（含用户用文件选择器授权的任意目录）
- WASI 沙箱里的 `sh` / coreutils / `python` / `node` / `git` / `rg` / `jq` / ImageMagick 子集
- 每个沙箱可设 CPU 时间、内存、磁盘写入、网络出口、执行时长上限；一次 `run` 失败不会污染主工作区（写时复制快照）
- 每次改动是一个**可回滚的检查点**：`/undo` 一步回到任意历史 Turn

**支柱二：多模型大脑（The Gateway）**
不赌任何一家模型，也不被任何一家锁死。
- 一等公民：OpenAI（Responses/Chat）、Anthropic（Messages + Prompt Caching）、Gemini、DeepSeek（含 reasoning、上下文缓存）
- 全量兼容：任何 OpenAI 兼容端点（Qwen/Kimi/GLM/Doubao/MiniMax/xAI/Groq/Cerebras/OpenRouter/vLLM/Ollama/LM Studio）
- **中转站原生支持**：自定义 Base URL、自定义 Header、模型名别名映射、按渠道覆盖价格表、渠道健康探测与自动降级
- **端侧模型作为一等公民**：Apple Foundation Models、MLX、llama.cpp；承担路由、摘要、标题、脱敏、离线兜底
- **路由策略是一等配置**：按任务类型（规划/编码/长文/视觉/低成本）选模型，自动 failover，带成本与配额熔断

**支柱三：常伴式体验（The Companion）**
桌面 Agent 只能在你坐下来时工作。手机可以一直陪着你。
- **Live Activity + 灵动岛**：任务在跑就在岛上呼吸；锁屏可看到进度、当前步骤、成本
- **语音全双工**：说话下任务、说话转向、说话批准（"同意" / "跳过这步" / "改一下，只改后端"）
- **Siri / App Intents / 快捷指令 / 操作按钮**：一键发起预设任务（"跑今日日报"、"看看有没有 CI 红的"）
- **分享即输入**：任何 App 里分享文本/文件/图片/URL 到 Rune，即成为一次任务的上下文
- **审阅为一等交互**：Diff 卡片左右滑动逐个接受/拒绝；长按 = 看原始上下文；摇一摇 = 撤销上一个检查点
- **锁屏续跑**：Turn 级检查点 + 静默推送唤醒，用户感知"它一直在跑"

## 4. "超越桌面 Agent"的可度量定义

不能只喊口号。Rune 给自己定四组可测指标（详见 [14](14-工程路线图与测试策略.md)）：

**A. 同级能力不缩水**（在手机硬件上对标桌面）

| 指标 | 目标 |
|---|---|
| SWE-bench-Verified 子集（30 题，本地仓库）通过率 | ≥ 桌面同模型基线的 **95%**（差距仅来自模型选择，不来自工具能力） |
| 典型任务工具调用成功率 | ≥ 99%（工具本身失败率 < 1%，不含网络） |
| 端侧 `rg` 扫描 10 万文件耗时 | ≤ 3s（首次热缓存后） |
| 端侧 `git status/log/diff` 大仓库响应 | ≤ 500ms |
| 单次 Turn 无人工干预完成率（简单任务） | ≥ 85% |

**B. 手机独有维度**（桌面做不到）

| 指标 | 目标 |
|---|---|
| 从"想到"到"任务开始跑"的耗时（语音） | ≤ 4s（含唤醒 + 转写 + 首 token） |
| 完成一个"中等任务"所需的**点击数** | ≤ 5 次（含 1 次语音） |
| 锁屏期间可推进的 Turn 占比 | ≥ 70% 的步骤可在后台/唤醒窗口内完成 |
| 出行场景（无电脑）任务完成率 | ≥ 桌面场景的 70% |

**C. 手感**

| 指标 | 目标 |
|---|---|
| 冷启动到可输入 | ≤ 600ms（P90） |
| 首 token 呈现 | ≤ 1.2s（网络正常） |
| 流式渲染掉帧 | 0 帧（120Hz ProMotion 下） |
| 单次完整 Turn 的电量成本（中等任务） | ≤ 3% 电量 |
| 崩溃率 | < 0.02% 会话 |

**D. 信任**

| 指标 | 目标 |
|---|---|
| 危险操作（删除/推送/付费/外发）需要显式确认的比例 | 100% |
| 每次第三方模型调用可预览发送内容 | 100% |
| 提示注入导致的越权工具调用（红队测试集） | 0 次成功 |
| 用户可在 10 秒内找到"这个 Agent 刚刚动了什么" | 100%（一次点击到审计页） |

## 5. 非目标（明确不做）

写下不做的事，比写下要做的事更重要。

| 不做 | 原因 |
|---|---|
| **不做云端代码执行** | 与定位直接冲突。任何"帮你在我们服务器跑一下"的功能都不做，包括"重任务卸载到云"。 |
| **不做手机 App 生成器** | 一是 App Store 2.5.2 高风险区（见 [11](11-AppStore合规与分发.md)），二是把产品做成玩具。Rune 面向的是**真实工程与数据任务**，产出是代码/文件/提交/报表。 |
| **不做社交/社区/模型市场** | 首版只做本地 Skill 目录 + 官方内置库；社区市场会引入审核与执行风险。 |
| **不强制订阅** | BYOK 模式下不做"必须买我的额度"。可选提供托管通道（走 IAP）作为便利项，但不是主路径。 |
| **不做自己的 IDE** | 编辑器只做到"审阅与轻改"级别（高亮、diff、逐块接受）。要写大段代码，用户会去桌面。 |
| **不做越狱/私有 API 依赖** | 必须能过审、能在量产机上跑。任何依赖未公开 API 的方案一律否决。 |
| **不追求"全自主"** | 默认人机协同：计划可见、危险可拦、随时可停。全自主模式是显式选项，不是默认。 |

## 6. 设计公理（由 iOS 现实推导，后续所有文档都以此为前提）

这十条是**不可协商的物理约束**，架构必须围绕它们生长：

| # | 公理 | 推导出的设计 |
|---|---|---|
| A1 | 无 `fork`/`exec` | 一切命令执行走 WASI 解释器（[05](05-工具系统与执行沙箱.md)） |
| A2 | 文件访问必须经用户授权 | 首启引导建立"工作区"，用 security-scoped bookmark 持久化目录授权 |
| A3 | 后台 ≤ 数十秒量级，且随时可能被回收 | Turn 级检查点 + 事件溯源 + 幂等重放（[10](10-后台执行与可靠性.md)） |
| A4 | 禁止下载执行改变功能的代码 | 所有运行时随包分发；Skill/Workflow 是**声明式数据**，不是下载的二进制 |
| A5 | JIT 受限 | 不用 JIT，WASM 走解释器 + AOT 预编译热点（[05](05-工具系统与执行沙箱.md)） |
| A6 | 内存上限严苛（设备相关，可低至 ~1.5GB） | 流式处理一切；大文件走 mmap + 分块；不把整个文件读进内存 |
| A7 | App 容器随时可能被 iCloud 备份/系统清理 | 大对象（对象存储、模型、缓存）标记为不备份；可重建的都可丢弃 |
| A8 | 屏幕小、键盘贵 | UI 以"卡片 + 手势 + 语音"为主，聊天只是其中一种视图 |
| A9 | 没有真正的守护进程 | "常驻感"由 Live Activity + 通知 + 唤醒补偿拼出来 |
| A10 | 用户手机会丢、会被别人拿到 | 生物识别锁 + 密钥存 Secure Enclave + 可远程（本地）擦除 |
| A11 | **内嵌 CPython 的 App ≈ 1GB 起步（实测：Pyto 930MB、Pythonista 853MB、a-Shell 1950MB），且因为是 2.5.2，运行时必须随包、不能"下载"** | **接受这个体积并把它变成卖点**："因为它把 Python 和你要用的库都装进来了，所以断网也能干活"；只用 On-Demand Resources 剥离纯数据（示例项目、库集合），解释器与工具链不剥离（[附录 B §11.10](附录B-技术选型核实表.md)） |

## 7. 附录：命名决策记录

**主名：Rune（符文）**

| 评估项 | 结论 |
|---|---|
| 语义 | rune = 刻在载体上的最小符号，承载力量。对应 Agent 的最小工作单元（一次工具调用 / 一段 diff / 一条记忆），也对应"编码"这件事的本源（书写符号） |
| 可读性 | 4 字母、单音节、中英文均可读（符文 / 鲁恩）；域内无主流 Agent 产品重名 |
| 延展性 | 子品牌自然：Rune Bench（工作台）、Rune Gateway、Rune Runes（Skill/工作流，双关）。中文"符文"在游戏语境中认知度高（符文页 = 能力配置），恰好对应"模型与工具的可配置组合" |
| 风险 | 需做商标与 App Store 名称查重；建议同时注册 `rune.run` / `runes.app` 一类域名 |

**已否决的备选**

| 名字 | 语义/理由 | 否决原因 |
|---|---|---|
| Kiln（窑） | 原料 + 火 → 成品，本地转化 | 读音在中文语境不响亮；窑=封闭感过强 |
| Hearth（灶火） | 属于你家的火，本地私有 | 气质偏家居，弱工程感 |
| Nabu | 美索不达米亚书吏之神 | 中文认知度低；与 Home Assistant Nabu Casa 冲突 |
| Flint（火石） | 兜里的工具制造者 | 与教育类 Flint AI 冲突明显 |
| Lathe（车床） | 工作母机，机器造机器 | 中文读音易混（lathe/lace） |
| Manus / Devin / Otto | — | 已有强势同名产品 |
