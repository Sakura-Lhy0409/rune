# Rune 原生界面 · C42 实现与验收

## 视觉方向

暖白画布 `#F5F3EE`、松绿主色 `#355B49`、石墨文字 `#202B24`；深色使用 `#141815` 与浅玉色强调。轻薄的分隔、清晰的文字层级、充足留白，不使用紫蓝渐变、机器人或星芒。RuneMark 是符文式 R。

玻璃集中在导航、浮动输入和工具操作层。`RuneUI/RuneTheme.swift` 在 iOS 26+ 调用真实 `glassEffect`，较旧系统用 Material；降低透明度时回退到实色。动态字体、减弱动效和深色配色分别处理，iPad 使用 NavigationSplitView。

**目标包含 iOS 27，但本机仅有 Xcode 26.6 / iOS 26.5 SDK。** 当前已验证的是 26.5；不能据此宣称已完成 27 SDK 编译、27 真机与其新增 API 的验收。

## 真实行为与未接入能力

本地文件演练执行真实读写，批准前不落地；用户编辑与撤销都先比对当前文件，防止覆盖后续修改。会话、配置、清单与偏好保存在 Application Support，API key 单独保存在 Keychain。界面进程重启后，正在执行的演练变为暂停。

自定义任务明确标为待连接，不假装已经调用模型。预算和信任设置当前是偏好；生产模型运行时、Git 引擎、后台调度、记忆检索、真正的 Workflow 执行与事件数据库接线仍未完成。界面 JSON 是展示状态，不替代 RuneStore 的运行时事件真相源。

相机与离线语音能力使用系统 API；硬件权限、真实录音识别、相机拍摄与完整分享面板往返仍需真机/专项验收。Live Activity 不等于获得无限后台执行时间。

## 工程与验证

- `RuneUI` 变为独立视觉组件/界面模型包，不再为展示状态引入 RuneCore 依赖。
- App 保留旧内核演示为设置里的诊断页。
- 新增 `RuneWidgets`、`RuneShare` 扩展 target，以及共享 ActivityAttributes、App Group 和 URL scheme。
- 模拟器使用 ad-hoc 签名才能实际获得 App Group；无签名构建仅证明代码可编译。
- 包测试：Kernel 1035 + Net 24 + Store 8 + UI 5 = **1072 项通过**；11 包构建与仓库审计通过。
- 主流程 UI：**9 项通过**，涵盖引导、文件编辑、目标、渠道、会话持久化、审阅/拒绝/撤销、系统实时活动。
- 灵动岛另作专项验证：ActivityKit 创建成功、退出 App 后紧凑态可见、长按展开可见、可回到任务。
- 已查看 iPhone 浅色、深色引导与 iPad 分栏截图。正式 27 SDK、真机硬件与各辅助功能组合不算已验收。
- App 与两个扩展的 Release iPhoneOS 构建通过；最后的分享文件 URL 修正会继续走构建检查。

测试源码在 `Apps/Rune/UITests/RuneSmokeTests.swift`；状态和 Diff 测试在 `Packages/RuneUI/Tests/RuneUITests/StudioModelTests.swift`。本机截图放在 `DesignReview/`（已忽略、不入库）；其中 `10-live-island-expanded.png` 为真实系统呈现，`07-live-activity.png` 是设置中的布局预览。
