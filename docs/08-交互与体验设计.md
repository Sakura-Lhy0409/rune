# 08 · 交互与体验设计

> **摘要**：桌面 Agent 的交互是"一个终端 + 一条文本流"。手机上照搬必然失败。
> Rune 的交互范式是：**会话 = 一串可操作的卡片；工作 = 一条可拖动的时间轴；控制 = 一根可拖动的信任刻度盘；输入 = 说话、拍照、分享、一个按钮。**
> 本文给出屏幕结构、手势表、语音协议、通知策略与关键界面草图。

---

## 1. 五条设计原则

| # | 原则 | 推导出的具体决策 |
|---|---|---|
| P1 | **一屏一决策** | 任何时刻屏幕上只有一个"需要你决定的事"，其余都是信息。绝不并排三个待批项。 |
| P2 | **结果优先于过程** | 默认折叠过程，展示产物卡片。想看过程，一个手势展开（过程不是默认视图）。 |
| P3 | **一切可撤销** | 每个产物卡、每次工具执行都有"撤销/回滚"入口。没有撤销路径的操作必须解释为什么。 |
| P4 | **确定性可见** | 模型、渠道、成本、剩余预算、当前信任档位，四个信息永远在会话头可见。 |
| P5 | **单手可达 + 语音等价** | 所有主要操作在拇指热区（屏幕下半部）；每个主要操作都有语音等价指令。 |

---

## 2. 信息架构

```
底部三区（Tab）
├─ ① 今日 Today       ← 首页：进行中的任务、待决策项、Goal 进度、收件箱
├─ ② 会话 Chats       ← 历史会话列表（按工作区分组，可搜索）
└─ ③ 工作台 Bench     ← 工作区管理：文件、Git、Runebook（技能）、Workflows、记忆

顶部全局（会话内）
├─ 会话头：模型徽标 + 渠道 + 成本累计 + 信任刻度盘 + ⋯
└─ 上下文胶囊：当前工作区 / 分支 / 未提交改动数

侧边（手势唤出）
├─ 左滑 → 时间轴（Time Machine）
└─ 右滑 → 工具与产物抽屉（本次会话产生的全部文件/表/图/报告）
```

**为什么是"今日"而不是"聊天列表"做首页**：手机 Agent 的价值在于"它在替你干活"，所以首页必须回答"现在有什么在跑、有什么需要我"。聊天列表是工具，不是主页。

```
└──────────────────────────────────────────────┘
```

**关键设计说明：**
- **过程折叠是默认**：`▸ 展开过程` 才显示 37 次工具调用。手机屏幕的价值是展示结果，不是展示忙碌。
- **产物卡片直接可操作**：`[✓][✗]` 逐个文件接受/拒绝，不用滚到别处。
- **验证徽标**：`● 已运行` / `○ 未验证` / `⚠ 失败` 三态，一眼看到"做完了但没验证"。
- **模型与成本在会话头常驻**：这是信任的基础。
- **转向按钮（↑）**：任务跑着也能加一句"等等，先备份"。

### 3.4 信任刻度盘

```
┌──────────────────────────────────────────────┐
│  信任级别                                     │
│                                              │
│   ○──────●───────────○──────────○────────○   │
│  只读   协作        提议        自治     全权  │
│           ▲                                  │
│                                              │
│  协作（当前）                                 │
│  ✓ 读工作区任意文件                           │
│  ✓ 在工作区内写文件、跑沙箱脚本                 │
│  ✓ 本地 git commit                            │
│  ✗ 推送/外发/删除/花钱 → 每次询问              │
│  ✗ 网络访问 → 白名单域名可直接访问              │
│                                              │
│  范围：项目 shop-api（仅本会话）               │
│  [应用到本项目]  [仅本会话]  [自定义策略…]      │
└──────────────────────────────────────────────┘
```

五档定义：

| 档位 | 写文件 | 执行脚本 | 网络 | Git | 危险操作 | 适用场景 |
|---|---|---|---|---|---|---|
| **只读** | ✗ | ✗（只许读类） | 白名单 | 只读 | 全拒 | 让你先看看、代码审计、陌生仓库 |
| **协作**（默认） | ✓ 工作区内 | ✓ 沙箱 | 白名单 | 提交 | 每次确认 | 日常 |
| **提议** | 生成 diff 但不落地 | ✓ 沙箱 | 白名单 | 不提交 | 全需确认 | "我想看方案，别动我的文件" |
| **自治** | ✓ 工作区内 | ✓ | 白名单+新域名询问 | 提交+推送 | 仅不可逆操作确认 | 熟悉项目、放手干 |
| **全权** | ✓ 任意授权目录 | ✓ | 任意 | 全部 | 不确认 | 高级用户 / 一次性沙箱项目 |

**刻度盘的两个关键规则：**
1. **Agent 不能改自己的刻度盘**（工具层不可写，见 [04](04-Agent运行时核心.md) §12）。
2. **每次上调解锁都要有"为什么这次需要"的一句话解释**，用户可以一键还原。

## 4. 输入方式（七条入口，全部等价）

| 入口 | 交互 | 触发方式 |
|---|---|---|
| **文字** | 输入框，支持 `/` 命令、`@` 引用文件、`#` 引用工具/技能 | 点击输入框 |
| **语音** | 长按 🎤 说话，松手发送；或"按住说话，上滑取消"；支持连续追加（全双工） | 麦克风按钮 / 耳机线控 / 操作按钮 |
| **相机** | 拍照 → 直接成为 Turn 的上下文（含 OCR/Vision 预处理） | 输入框旁相机按钮 / 分享 / 锁屏小组件 |
| **分享** | 任意 App 分享 文本/URL/文件/图片 → 落入收件箱 | 系统分享面板 |
| **文件** | 从"文件"App 拖入或选择 | 拖放 / 文件选择器 |
| **Siri / 快捷指令** | "嘿 Siri，用 Rune 看 CI" / 快捷指令编排 | **App Intents（这是接入 Apple Intelligence / Siri 的唯一路径**，不存在单独的"注册为 Apple Intelligence App Action"的 API）。iOS 27 新增 **App Schemas + domains**（如 `@AppEntity(schema: .messages.message)`）、`IndexedEntity`、以及基于 UserActivity/视图注解的**屏幕内容感知**，应当尽早接入 |
| **操作按钮 / 锁屏小组件 / 控制中心** | 一键发起预设任务 | 长按操作按钮 / 锁屏组件 |

### 4.1 语音协议（这是手机赢桌面的关键）

**基础指令集（无需唤醒词，在 Rune 内直接说）：**

| 说 | 动作 |
|---|---|
| "跑 / 开始 / 干" | 发送当前输入 |
| "等一下 / 先别" | 软暂停（停在当前步骤边界） |
| "停 / 打住" | 硬中断 |
| "同意 / 批准 / 可以" | 批准当前待批项 |
| "不行 / 拒绝" | 拒绝并让模型改方案 |
| "跳过这步" | 跳过当前步骤，继续后续 |
| "回滚 / 撤销" | 回到上一个检查点 |
| "再说一遍 / 念给我听" | 朗读最近一段总结（TTS） |
| "改成…" / "顺便…" | 转向（steer）正在跑的 Turn |
| "继续" | 恢复暂停的 Turn/Goal |

**设计要点：**
- **优先端侧语音识别**（Speech 框架的 on-device 模式）→ 零延迟、零流量、不上传。
- **说话时实时显示在输入框**，用户能看到转写并手动修正后再发送（避免"说错了一堆"）。
- **批准类语音必须二次确认**（说"同意"后 UI 高亮对应项 1.5 秒，可撤销），防止误批危险操作。
- **危险操作永远不接受纯语音批准**（推送/删除/花钱必须点击或生物识别）。

### 4.2 输入框的符号语法

| 符号 | 作用 | 例子 |
|---|---|---|
| `/` | 命令（内置 + Workflow + Skill） | `/ci`、`/report`、`/trust` |
| `@` | 引用文件/目录（带模糊搜索） | `@src/money.py`、`@tests/` |
| `#` | 强制指定工具或技能 | `#grep_search`、`#flaky-test-triage` |
| `$` | 指定模型/渠道（本次） | `$opus`、`$deepseek`、`$relay-a` |
| `!` | 直接执行（跳过规划，快速任务） | `!计算这个 CSV 的行数` |

## 5. 审批交互（手机上最容易做坏的地方）

### 5.1 三条铁律

1. **非阻塞**：审批卡出现在会话流里，不弹模态框。用户可以继续输入、继续看别的。
2. **批量**：同一轮里的多个待批项合并成一张卡，一次决定（"这 4 项都允许"）。
3. **可记忆**：每个决定都可以选择"记住（本项目/该目录/该工具）"，写回策略文件。

### 5.2 审批卡形态

```
┌── 需要批准 ────────────────────────────────┐
│ ⚠ 推送 3 个提交到 origin/main               │
│                                            │
│ fix: correct refund rounding       +42 −17 │
│ test: add currency exponent cases  +18  −0 │
│ chore: bump deps                     +2  −2│
│                                            │
│ 影响：远程 main 分支 · 将触发 CI 与部署流程  │
│ 可撤销：可以（本地 revert + 强推需再次确认）  │
│                                            │
│ [查看完整 diff]  [只看文件列表]              │
│                                            │
│ [拒绝]        [仅本地提交]      [推送 ✓]     │
│  ☐ 记住：以后对本项目允许自动推送             │
└────────────────────────────────────────────┘
```

**必须展示的四件事**：做什么、影响什么、能不能撤销、为什么现在做。缺任何一个，用户都会盲点"允许"。

### 5.3 按风险分级的审批方式

| 风险 | 方式 | 延迟 |
|---|---|---|
| 低（读外部 URL、装纯 Python 包） | 卡片内联"允许一次" | 0 点击（3 秒后自动允许，可撤销） |
| 中（写文件、跑脚本、本地提交） | 卡片 + 一键 | 1 点击 |
| 高（推送、外发数据、删除） | 卡片 + 展示细节 + 点击 | 1-2 点击 |
| 极高（支付、凭据修改、提权） | 卡片 + **生物识别** | 1 次 Face ID |
| 不可逆且高危 | 卡片 + 生物识别 + **手输确认词** | 多步 |

## 6. 产物卡片（Artifact Cards）

Agent 的产出不是一段文字，而是**可操作的类型化卡片**。这是"结果优先"原则的落地。

| 卡片类型 | 卡片内容 | 可用操作 |
|---|---|---|
| **代码改动** | 文件列表 + 每文件 ± 行 + 折叠 diff | 逐块接受/拒绝、展开、回滚 |
| **新文件** | 路径 + 类型图标 + 大小 + 预览 | 打开、分享、在文件 App 中显示 |
| **测试报告** | 通过/失败/跳过计数 + 首个失败详情 + 耗时 | 重跑失败项、展开日志 |
| **数据表** | 前 10 行表格 + 行列数 + 列类型 | 排序预览、导出 CSV/Excel、生成图表 |
| **图表** | 渲染图（可缩放） | 分享、导出 PNG/SVG、改类型（柱状/折线/饼） |
| **文档/报告** | Markdown 渲染 + 目录 | 导出 PDF/Markdown、复制、继续编辑 |
| **提交** | commit hash + 信息 + 文件数 | 查看、撤销、推送、开 PR |
| **PR** | 标题 + 目标分支 + 变更统计 + CI 状态 | 打开链接、请求评审、关闭 |
| **图片** | 缩略图 | 保存到相册、分享、继续处理（缩放/裁剪） |
| **网页摘要** | 标题 + 要点 + 来源链接 + 抓取时间 | 打开原文、存为记忆、基于此追问 |
| **待办** | 清单（可勾选） | 直接勾选（同步回 Reminders） |
| **失败/受阻** | 明确原因 + 已尝试的 3 种办法 + 需要你做的一件事 | 一键执行"需要你做的那件事" |

**设计规则**：每张卡片必须能"独立分享出去"。用户把卡片转发给同事时，对方应该能看懂（含足够上下文，不含内部句柄）。

## 7. Diff 审阅手势

| 手势 | 动作 |
|---|---|
| 左滑卡片 | 拒绝该文件的改动（回滚该文件） |
| 右滑卡片 | 接受该文件的改动（确认保留） |
| 上滑 | 展开完整 diff |
| 下滑 | 折叠为一行摘要 |
| 长按某行 | 选中该行 → 菜单（"只保留这行"、"解释这行为什么改"、"回到改之前"） |
| 双指拖动 | 逐块审阅模式（每按一次"下一个"跳到下一个 hunk） |
| 摇一摇 | 撤销上一次文件改动 |

**"解释这行为什么改"**是一个杀手级小功能：长按任意改动行 → 端侧模型或主模型用一句话解释动机。用户不必读完整推理链就能信任改动。

## 8. 通知与常驻（Live Activity / 灵动岛 / Widget）

### 8.1 Live Activity 内容（锁屏与灵动岛）

| 状态 | 紧凑（灵动岛） | 展开（锁屏） |
|---|---|---|
| 运行中 | `▶ 5/8` + 进度环 | 任务标题、当前步骤、进度条、成本、暂停按钮 |
| 等待决策 | `⚠ 1` 徽标 | "要推送到 origin/main 吗？" + 三个动作按钮（**可在锁屏直接点**） |
| 完成 | `✓` | 结果摘要 + "查看产物" |
| 受阻 | `⛔` | 阻塞原因 + "需要你做的事" |
| 空闲 | 不显示 | 不显示 |

**灵动岛上的三个动作按钮是产品的核心仪式感**：地铁里长按灵动岛 → 直接批准 → 收工。这是桌面 Agent 永远给不了的体验。

### 8.2 通知策略（防止变成骚扰源）

| 事件 | 是否通知 | 例外 |
|---|---|---|
| Turn/Goal 完成 | ✅ | 用户正在 App 内 → 不通知 |
| 需要决策 | ✅（立即） | 免打扰/Focus 时静默，但仍进"今日" |
| 长时间无进展（>5 分钟无新步骤） | ✅ | — |
| 失败 | ✅ | 可重试的自动失败（渠道降级）不通知 |
| 中间步骤完成 | ❌ | 除非用户显式开启"每一步都告诉我" |
| 成本超预算 | ✅（合并为一条/小时） | — |

**Focus 过滤器**：提供"仅决策与完成"与"全部"两档，接入系统 Focus。

### 8.3 Widget（桌面/锁屏）

| Widget | 内容 | 交互 |
|---|---|---|
| 小号 | 进行中任务的进度环 | 点击进入会话 |
| 中号 | 进行中 + 1 个待决策项 | 直接批准（App Intent） |
| 大号 | 今日概览：任务、成本、Goal 进度、收件箱 | 多个一键入口 |
| 锁屏 | 单行状态 + 一个快捷入口 | 一键跑"看 CI" |

**快捷发起 Widget** 支持用户自定义 4 个一键任务（例如"看 CI"、"今日日报"、"审我的 PR"、"整理收件箱"）。

## 9. 收件箱与规则

**分享即输入**：任何 App 里分享内容到 Rune，落入 `/inbox`。

```
收件箱
├─ 每条：类型图标 + 名称 + 来源 App + 时间 + 预览
├─ 动作：[指派给 Agent] [仅保存] [删除]
└─ 规则（可选）：
   - 来自「邮件」的 PDF → 提取要点并生成摘要
   - 来自「GitHub」的 PR 链接 → 自动跑 pr-review 技能
   - 截图 → OCR 后等待指令
```

**为什么需要规则**：手机用户的输入是碎片化的、随手发生的。没有规则，收件箱会变成垃圾场。规则是"自动化"最容易被接受的形态（比"Agent 自主决定"更可控）。

## 10. 键盘扩展与文本工具

**痛点**：用户在邮件/Slack/备忘录里写东西时，最想要"让 Agent 帮我把这段改写/翻译/续写"。

**方案**：键盘扩展（内存 ≤ 60MB，**绝不加载运行时会话**）
- 功能：改写、翻译、润色、扩写、缩短、改语气、修语法、解释选中文字
- 实现：调用 Gateway 的**轻量单次请求**（无工具、无历史）
- 隐私：默认不发送上下文（只发选中文本）；UI 明确标注"将发送你选中的 37 个字符"
- **完全开放的键盘权限警告**：遵循 Apple 要求，明确提示"完全访问"的含义，默认不开

**文本工具的另一个形态**：系统级"服务"（Share Sheet 动作）——选中文本 → 分享 → "Rune 改写"。

## 11. 触觉与声音（被忽视的体验层）

| 事件 | 触觉 | 声音 |
|---|---|---|
| 工具调用开始 | 轻点（`.light`） | 无 |
| 工具调用成功 | 微弱（几乎不可感） | 无 |
| 工具调用失败 | 双轻点（`.rigid`） | 无 |
| 需要审批 | 明显（`.medium` 两下） | 无（可配置） |
| 危险操作被拒 | 强（`.heavy`） | 警告音（可关） |
| 任务完成 | 上升式（自定义 pattern） | 柔和提示（可关） |
| 成本超阈值 | 无触觉（避免惩罚感） | 无 → 只更新 UI |
| 语音转写中 | 每 200ms 微振（表示在听） | 无 |

**原则**：触觉只用于"状态变化"，不用于"催促用户"。**永不因为"Agent 想让你快点决定"而震动。**

## 12. Onboarding（首次体验，60 秒内必须跑通第一个任务）

```
步骤 1  一句话说明（不啰嗦）
       "Rune 在你的手机上干活。代码、文件、记忆都不离开这台设备。"

步骤 2  选工作区（唯一必须做的事）
       [选择一个文件夹] · [先用示例项目试试]
       说明："Rune 只能访问你选中的文件夹。"（安全感的第一次建立）

步骤 3  配一个模型（可跳过）
       一键导入：OpenAI / Anthropic / Gemini / DeepSeek
       或：[自定义端点（中转站/局域网）] → Base URL + Key + 拉取模型列表
       或：[先用本机模型（无需 Key）]

步骤 4  第一个任务（自动预填，一键运行）
       "看看这个项目是做什么的，帮我写一份 README。"
       → 立刻看到它读文件、写文件、生成产物卡片

步骤 5  权限与信任（简短）
       "当前信任级别：协作。你可以随时调整。"
       [看看它刚才都做了什么] → 展示审计摘要
```

**硬性指标**：从打开 App 到看见第一个产物卡片，**≤ 60 秒，≤ 5 次点击**。

## 13. 空态、错误态与"无聊时刻"

| 场景 | 界面 |
|---|---|
| 无会话 | 展示 4 个"一键任务"建议 + 一句"试试说：看看这个项目" |
| 无网络 | 顶部细条："离线中 · 使用本机模型 Qwen3-4B" + [切换模型] |
| 无工作区 | 引导选择目录（不能只显示错误） |
| 无 API Key | 引导配置（提供"先用本机模型"的逃生口） |
| 任务跑得久 | Live Activity + 会话内步骤流 + "预计还需 2 分钟"；超过 5 分钟无进展 → 主动询问 |
| 沙箱失败 | 折叠的错误详情 + "已自动重试 1 次" + [看看哪里出错] |
| 预算耗尽 | 三选一卡片（见 [04](04-Agent运行时核心.md) §14） |
| 系统杀后台 | 恢复时："任务在 09:14 被打断，已从检查点恢复（跳过 3 个已完成步骤）" |

## 14. 手感细节（会被用户直接感知的部分）

| 细节 | 要求 |
|---|---|
| 流式文字渲染 | 按行批量刷新（每 ~50ms 或 32 字符），不是逐字符 setState；长文本用 `Text` 拼接优化 |
| 代码高亮 | 增量高亮（只重新高亮变化的行），大文件用视口渲染 |
| 滚动 | 流式内容**不抢滚动位置**（用户往上滚了就停止自动跟随，出现"跳到底部"按钮） |
| 列表 | 复杂卡片用 `LazyVStack` + 固定高度估算，避免布局抖动 |
| 大 diff | 首屏只渲染可见 hunk，其余按需 |
| 触感延迟 | 触觉反馈与视觉反馈必须同帧（否则感觉"卡"） |
| 键盘 | 发送后键盘不收起（连续对话）；危险操作确认时才收起 |
| 后台返回 | 从后台回来时**立即显示缓存状态**，再异步对账（不阻塞在数据库上） |
| 冷启动 | ≤ 600ms 到可输入；会话内容异步加载（先骨架屏） |
| 电量感知 | 低电量模式下 UI 上明确显示"已降级：跳过验证步骤" |

## 16. 无障碍（不能省）

| 项 | 要求 |
|---|---|
| VoiceOver | 每张卡片有完整语义标签（"代码改动卡片，3 个文件，增加 42 行，减少 17 行，可操作"）；进度用 `accessibilityValue` |
| 动态字体 | 全部支持到 AX5；卡片布局在超大字号下改为"标题 + 折叠详情" |
| 减弱动效 | 尊重系统设置，关闭呼吸/流动动画 |
| 对比度 | 流式文字、状态徽标满足 WCAG AA |
| 语音替代 | 所有视觉操作都有语音等价（这是天然优势） |
| 触觉替代 | 关键状态同时有视觉与语音提示（不依赖触觉） |
| 色盲 | 状态不用纯色区分（✓/○/⚠ 图标 + 文字） |

## 17. UI 构件选型（已核实，避免重复造轮子）

| 需求 | 选择 | 状态 | 备注 |
|---|---|---|---|
| **流式 Markdown 渲染** | ⭐ **microsoft/SwiftStreamingMarkdown** | 微软官方维护，**专为 LLM 流式输出设计** | 这是最贴合我们场景的一个构件，**优先采用** |
| Markdown（通用） | swift-markdown（**仅 parser，无渲染器**）；**MarkdownUI 已进维护模式**（官方建议迁移到 **Textual**） | — | 新开发用 SwiftStreamingMarkdown + Textual 组合 |
| **代码编辑器** | **CodeEditorView**（纯 SwiftUI，TextKit 2，活跃）或 **Runestone**（更成熟但 UIKit API，需自写 SwiftUI 包装） | 两者生产可用 | 我们的编辑器只需"审阅 + 轻改"级别，**优先 CodeEditorView**（SwiftUI 集成成本低） |
| 语法高亮 | HighlightSwift / SwiftSyntaxHighlighter | 生产可用 | ⚠️ Highlightr 较慢、Splash 已停维护 → 不用 |
| 符号索引（tree-sitter） | **SwiftTreeSitter** + 预打包的 grammar（`tree-sitter-xcframework`） | 引擎可用，**grammar 与 `.scm` 查询需自行打包** | 需自研兜底，是 [07 §3.1](07-上下文与记忆引擎.md) L1 符号索引的基础 |
| 终端视图 | **SwiftTerm**（Xterm/VT100，活跃维护，有 DocC） | 生产可用 | 用于"展开脚本输出"的原始视图；不做成主界面 |
| **Diff 视图** | ⚠️ **不存在成熟的 SwiftUI 并排 diff 组件** | **需自研** | 用 `CollectionDifference`（SE-0240）+ `DiffableDataSource` 自建；这正是 [§7 Diff 审阅手势](#7-diff-审阅手势) 的实现基础，**要预留工时** |
| 图表渲染 | 原生 Swift Charts + Core Graphics 导出 PNG/SVG | 系统框架 | 用于产物卡片里的图表 |

**两条工程提示**：
1. **编辑器与 diff 视图是自研工作量最大的两块**（尤其 diff 的手势交互与逐块审阅），排期时不要低估。
2. **tree-sitter 的 grammar 打包有额外成本**（每种语言一个 `.xcframework` 或 bundle），因此**首批只支持 4-6 种语言**（Swift / Python / TypeScript / Go / Rust / Java），其余语言退化为"纯文本高亮"。
