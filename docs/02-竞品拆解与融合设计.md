# 02 · 竞品拆解与融合设计

> **摘要**：Rune 的能力基线不是"自己发明"，而是**把三个已经验证过的 Agent 范式拆成零件，按移动端的物理约束重新组装**。本文逐个拆解 Codex CLI、Claude Code、DeepSeek Harness（DSH），给出"取什么 / 改什么 / 弃什么"的三态决策，并裁决三家做法冲突时听谁的。

---

## 1. 拆解维度

用九个维度横向切开三个参照系，才能看清哪些是"范式"（必须继承）、哪些是"实现选择"（可以替换）。

| 维度 | 问题 |
|---|---|
| D1 执行模型 | 工具在哪里跑？沙箱边界在哪？审批点在哪？ |
| D2 工具集 | 有哪些原语？工具契约长什么样？ |
| D3 上下文管理 | 系统提示怎么组织？项目指令文件是什么？什么时候压缩？ |
| D4 扩展机制 | 用户怎么加能力？（Skill/Plugin/MCP/Hook） |
| D5 多智能体 | 有没有子代理？怎么并发？怎么汇总？ |
| D6 状态与恢复 | 会话怎么存？能回滚吗？能断点续跑吗？ |
| D7 交互形态 | 人怎么介入？（审批、转向、计划模式、中断） |
| D8 安全模型 | 谁能动什么？不可信内容怎么处理？ |
| D9 分发与商业化 | 开源？订阅？BYOK？ |

## 2. Codex CLI —— 工程纪律与沙箱范式

### 2.1 它的真正优势（不是"OpenAI 的模型"）

| 优势 | 具体表现 | Rune 的评估 |
|---|---|---|
| **C1 沙箱即产品** | 把"能执行到什么程度"抽象成 **sandbox policy × approval policy** 的二维矩阵：read-only / workspace-write / danger-full-access × untrusted / on-failure / on-request / never。一个配置文件就能表达"我信任你到什么程度" | **必须继承，且要做成 UI 上的"信任刻度盘"**（见 [08](08-交互与体验设计.md)、[09](09-安全与隐私威胁模型.md)）。这是 Rune 安全模型的主干。 |
| **C2 结构化补丁原语** | 不靠自由文本 `sed`，而是专门的补丁工具（`apply_patch` 式自由格式 diff），一次调用完成多处编辑，且**补丁本身可校验、可回滚** | **必须继承，并升级为移动端友好的"diff 检查点"**：每个补丁自动成为一个可视化检查点，支持逐块接受（见 [04](04-Agent运行时核心.md)） |
| **C3 项目指令文件** | `AGENTS.md` 分层加载（仓库根 → 子目录 → 用户全局），是"项目记忆"的事实标准 | 继承，落地为 `RUNE.md` + **兼容读取 `AGENTS.md` / `CLAUDE.md`**（迁移友好，见 [07](07-上下文与记忆引擎.md)） |
| **C4 事件流式会话日志** | 会话以 JSONL/结构化事件落盘（可 `resume`），是"事后审计 + 断点恢复"的基础 | 继承并强化：Rune 的会话就是**一张事件表**（event sourcing），这是 A3 公理下后台续跑的唯一解法（见 [12](12-数据模型与持久化.md)） |
| **C5 非交互模式** | `exec` 式无头运行 + 结构化输出，可接 CI/脚本 | 继承为 **Shortcuts/App Intents/URL Scheme 三种无头入口**（手机上的"CI"就是快捷指令） |
| **C6 精简原语** | 工具数量克制，靠 shell 兜底（`shell` 工具 + 转义权限申请） | **部分否决**：手机上"靠 shell 兜底"前提不成立（无 fork），必须把 shell 变成沙箱内解释器，因此工具集要更"厚"（见 [05](05-工具系统与执行沙箱.md)） |
| **C7 双协议支持** | 同时吃 Chat Completions 与 Responses（含 reasoning item 与缓存 token 语义） | 继承：Rune Gateway 的"协议族"抽象必须原生区分这两者（见 [06](06-模型网关与中转站.md)） |

### 2.2 它没解决的（Rune 的机会）

- **只面向桌面与终端**：没有移动生命周期概念，没有"任务被打断后如何呈现"。
- **模型锁定在自家**：reasoning 语义、缓存语义绑定 OpenAI，换家模型能力断崖。
- **交互是 TUI**：单栏文本流，在手机上等于不可用。
- **没有"常伴"**：不跑就不存在。用户不会知道"昨天那个任务后来怎样了"。

## 3. Claude Code —— 工具循环的可扩展性与人机协同

### 3.1 它的真正优势

| 优势 | 具体表现 | Rune 的评估 |
|---|---|---|
| **A1 工具集"尺寸刚好"** | Read / Write / Edit / MultiEdit / Glob / Grep / Bash / TodoWrite / Task / WebFetch / WebSearch / NotebookEdit —— 十几个原语覆盖 95% 场景，且每个工具的输出都被设计成"给模型看的、压缩过的" | **直接继承工具语义**（名字可换，语义必须一致），因为模型对这套语义的"肌肉记忆"最强（见 [05](05-工具系统与执行沙箱.md#2-工具目录)） |
| **A2 渐进式披露的 Skill** | `SKILL.md` + frontmatter（name/description），模型先看到**目录**，按需加载全文，避免长期占用上下文 | **继承为 Rune Runes（技能）**，并额外支持"技能包 = 指令 + 工具白名单 + 示例 + 夹具文件"（见 [04](04-Agent运行时核心.md#7-技能skills与渐进式披露)） |
| **A3 Hook 机制** | 在 PreToolUse / PostToolUse / Stop / SessionStart 等生命周期点插入用户脚本 | **继承但要换形态**：手机不能跑任意脚本，改为**声明式 Hook（条件 + 动作）**，动作可以是"发通知/写日志/请求确认/调用另一个 Skill/发网络请求"（见 [04](04-Agent运行时核心.md#9-hooks钩子)） |
| **A4 计划模式（Plan Mode）** | 显式区分"只许想、不许动"的规划阶段与"开始动手"的执行阶段，用户批准计划后才放行写入 | **继承并做成 UI 主状态之一**：手机上"先看计划再放行"比桌面更重要，因为误操作代价更高（不可轻易 undo 的移动场景） |
| **A5 TodoWrite 式任务清单** | 让模型显式维护待办，形成自监督循环，显著降低"跑偏/半途而废" | **继承且强化为可见 UI**：手机上是**进度卡片**而不是内部状态，用户可以点开逐项查看/取消（见 [08](08-交互与体验设计.md)） |
| **A6 子代理与上下文隔离** | Task/Agent 工具把重活丢进独立上下文的子代理，只回传摘要 | **继承并升级**：手机内存有限，子代理必须**共享同一进程、可配置并发度、可被系统回收且可恢复**（见 [04](04-Agent运行时核心.md#6-子代理subagents与并发)） |
| **A7 检查点与回滚** | 会话级 rewind：回到之前某一步重新开始 | **继承为移动端核心手势**：摇一摇撤销 / 长按时间轴跳转；这是"敢让 Agent 动手"的心理前提 |
| **A8 上下文压缩工程** | 自动压缩 + 手动 `/compact`，保留"关键决策与未完成事项"而非全文摘要 | **继承**，并针对移动端**成本敏感**做增强：压缩前先做端侧摘要，减少一次大模型调用（见 [07](07-上下文与记忆引擎.md#5-压缩compaction)） |
| **A9 权限规则DSL** | settings 中的 allow/deny 规则（工具 + 模式匹配），可提交进仓库共享 | **继承为"能力策略文件"** `rune.policy.toml`，可随项目分发（见 [09](09-安全与隐私威胁模型.md#4-能力策略语言)） |
| **A10 MCP 双向** | 既是 MCP 客户端（接外部 server），也能作为工具被别的系统调用 | **继承双向**：Rune 作为 MCP **客户端**（接远程/本地 MCP server），同时作为 MCP **服务端**暴露给桌面 Agent（"用手机当桌面 Agent 的工具箱"——这是杀手级反向场景，见 [04](04-Agent运行时核心.md#11-mcp-双向)） |
| **A11 Headless / SDK 化** | 可编程接口，能被别的程序驱动 | 继承为 App Intents + URL Scheme + 本地 XPC 式进程内 API |

### 3.2 它没解决的

- **重后台依赖**：Bash 工具直接把宿主 shell 暴露给模型，安全边界靠审批而非沙箱，在手机上完全不可行。
- **上下文成本不透明**：用户看不到"这次请求花了多少钱、缓存命中多少"。
- **单模型族**：Claude 优先，换模型时工具行为（尤其 Edit 的精确性）会退化。
- **桌面 TUI 假设**：输出流是"终端的形状"，长 diff 滚动阅读体验在手机上是灾难。

## 4. DeepSeek Harness（DSH）—— 长任务的编排与记忆

> 这是本设计所处的运行环境本身，因此拆解基于**直接观察**而非公开资料。

### 4.1 它的真正优势

| 优势 | 具体表现 | Rune 的评估 |
|---|---|---|
| **H1 Goal（目标）跨轮持续** | `create_goal` / `get_goal` / `update_goal`：一个长目标被持久化，运行时在**自动续跑轮次**里持续推进，直到完成或阻塞；阻塞需要"同一条件连续 ≥3 轮"才允许标记，避免模型轻易放弃 | **最高优先级继承**。这是"手机 Agent 能做到桌面做不到的事"的关键：桌面 Agent 一次会话结束就完了，Goal 让任务跨越"锁屏—唤醒—断网—换地方"（见 [04](04-Agent运行时核心.md#5-目标goals跨轮推进)） |
| **H2 Workflow（脚本化多代理编排）** | 用一段 JS 脚本描述 `phase` / `agent(prompt, schema)` / `pipeline` / `parallel`，把扇出、阶段、结构化结果都写成可复现的编排 | **继承为 Rune Workflow**：手机上是"一键跑一整套流程"的载体（例如"发版检查"＝17 个并行检查）。脚本语言用 **JavaScriptCore**（无需额外运行时，见 [05](05-工具系统与执行沙箱.md#5-js-沙箱javascriptcore)） |
| **H3 后台作业（Background Jobs）** | `job_list` / `job_output`（支持增量读取与 wait）/ `job_kill`：长命令转后台，不阻塞主循环；输出可增量消费 | **继承映射到 iOS 生命周期**：Job 状态机 + 检查点，把"等待"变成"可挂起"（见 [10](10-后台执行与可靠性.md)） |
| **H4 分层沙箱模式** | read-only / workspace-write / danger-full-access 三档，与"审批提示可禁用"的解耦设计 | 继承：直接对应 Rune 的三档"信任刻度盘" |
| **H5 Skill 目录 + 按需加载** | 会话开始时只注入技能清单（名称 + 一句话），模型按需 `skill(name)` 拉全文 | 继承，与 Claude Code 的 Skill 合并为同一机制（避免两套） |
| **H6 记忆库（Hindsight 式）** | "知识页 + 原始记忆"双层：**策展过的知识页**用于快速检索，底层原始记忆（会话、提交、文档）用于深挖；还提供 `reflect` 做跨记忆推理，`capture_initiative` 记录计划变更 | **继承为 Rune Memory 三层结构**（工作记忆 / 项目知识页 / 原始事件），并把 `capture_initiative` 变成"计划变更留痕"的自动行为（见 [07](07-上下文与记忆引擎.md#6-三层记忆)） |
| **H7 Ralph 式全新上下文迭代** | 每一轮用全新子代理、以工作区为长期记忆，避免上下文污染 | **继承为"Fresh Run"模式**：手机上的长任务可开启"每轮全新上下文"，代价是每轮重读，收益是抗漂移 |
| **H8 Todo 纪律** | 强制显式 todo 列表并在完成瞬间更新（不许批量补记） | 继承，作为系统提示的硬约束 |
| **H9 可交付物（Artifact）管道** | 不只是吐文本，而是产出**类型化制品**（文档、演示、图片、附件）并直接回传给用户 | **继承为核心体验**：Rune 的产物是"卡片"（diff / 图 / 表 / 报告 / PR），不是聊天文字（见 [08](08-交互与体验设计.md#6-产物卡片artifact-cards)） |
| **H10 运行时可观测** | 工具调用、作业状态、上下文占用对用户可见可干预 | 继承并移动化：**Live Activity 就是 DSH 的作业面板** |
| **H11 严格的"不越界"人格** | 明确的失败上报纪律（不谎报成功、不隐藏阻塞、不总结未做之事） | **继承为 Rune 的输出契约**：见 [04](04-Agent运行时核心.md#12-输出契约与诚实性约束) |

### 4.2 它没解决的

- **桌面/服务器假设**：Goal 与 Job 的推进依赖"进程一直活着"，iOS 上必须换成检查点续跑。
- **单模型族**：围绕 DeepSeek 的行为特征调优。
- **交互是"文本 + 面板"**：没有语音、没有手势、没有移动生命周期。

## 5. 三角交叉对比

| 维度 | Codex CLI | Claude Code | DSH | **Rune** |
|---|---|---|---|---|
| 执行模型 | OS 级沙箱（Seatbelt/Landlock）+ 审批矩阵 | 审批为主 + 沙箱为辅 | 三档文件沙箱 | **WASI 虚拟机 + 能力令牌 + 三档信任刻度盘** |
| 命令执行 | 真实 shell/fork | 真实 shell/fork | OS 进程 | **解释执行的 WASI sh + 原生工具** |
| 工具集 | 精简（靠 shell） | 中等（10+ 原语，语义最佳） | 中等 + 编排工具 | **Claude 语义 + 移动原生工具 + 编排工具** |
| 项目记忆文件 | AGENTS.md | CLAUDE.md | 项目指令 | **RUNE.md（兼容读 AGENTS/CLAUDE）** |
| 扩展 | MCP + 配置 | Skill / Hook / MCP / Subagent / Plugin | Skill / Workflow / 子代理 / Ralph | **Rune（Skill）/ Workflow / Hook 声明式 / MCP 双向** |
| 多代理 | 有限 | Task 子代理 | 子代理 + Workflow 扇出 + Ralph | **子代理（进程内）+ Workflow（JSC）+ Fresh Run** |
| 长任务 | resume 会话 | 会话回滚 | **Goal + Job（最强）** | **Goal + Job + 检查点续跑（移动版最强）** |
| 状态 | JSONL 会话 | 会话 + rewind | 会话 + 目标 + 作业 | **事件溯源 SQLite + 检查点 + 时间轴 UI** |
| 安全 | 强（OS 沙箱） | 中（审批） | 中（文件沙箱 + 审批可关） | **强（无 OS 权限可给，靠 VM + 能力令牌 + 出口白名单）** |
| 记忆检索 | 无（靠 grep） | 无（靠 grep） | **知识页 + 向量检索 + reflect** | **混合检索（BM25+向量）+ 三层记忆** |
| 交互 | TUI | TUI + IDE | 桌面 GUI + 面板 | **移动原生：卡片/语音/手势/常驻** |
| 模型 | OpenAI 优先 | Anthropic 优先 | DeepSeek 优先 | **完全模型无关（含端侧）** |
| 后台 | 无（进程活着） | 无 | 有作业 | **iOS 生命周期适配的检查点续跑** |

## 6. 借鉴矩阵（Take / Adapt / Reject）

### 6.1 直接取（Take）—— 范式正确，原样搬

| 来源 | 能力 | 落地位置 |
|---|---|---|
| Claude | 工具语义（Read/Write/Edit/Glob/Grep/TodoWrite/Task 等） | [05](05-工具系统与执行沙箱.md) 工具目录 |
| Claude | Skill 渐进式披露 | [04](04-Agent运行时核心.md) §7 |
| Claude | Plan Mode | [08](08-交互与体验设计.md) §3.2（计划卡片与批准流）、[04](04-Agent运行时核心.md) §3 |
| Claude | 检查点回滚 | [04](04-Agent运行时核心.md) §10 |
| Claude | MCP 双向 | [04](04-Agent运行时核心.md) §11 |
| Codex | sandbox × approval 二维矩阵 | [09](09-安全与隐私威胁模型.md) §3 |
| Codex | 结构化补丁原语 | [04](04-Agent运行时核心.md) §4 |
| Codex | AGENTS.md 分层加载 | [07](07-上下文与记忆引擎.md) §4 |
| Codex | 事件流会话日志 + resume | [12](12-数据模型与持久化.md) |
| DSH | Goal + 自动续跑轮次 + 阻塞判定纪律 | [04](04-Agent运行时核心.md) §5 |
| DSH | Workflow 脚本化编排（phase/agent/pipeline/parallel） | [04](04-Agent运行时核心.md) §8 |
| DSH | Background Job 状态机 | [10](10-后台执行与可靠性.md) §3 |
| DSH | 三层记忆 + reflect | [07](07-上下文与记忆引擎.md) §6 |
| DSH | 类型化可交付物 | [08](08-交互与体验设计.md) §6 |
| DSH | 诚实性输出契约 | [04](04-Agent运行时核心.md) §12 |

### 6.2 改造后用（Adapt）—— 范式对，但必须在手机上换实现

| 来源 | 原形态 | 移动端改造 | 为什么必须改 |
|---|---|---|---|
| Claude | Bash 工具 | **WASI `sh` 沙箱 + 结构化原语工具**：模型仍然可以"写 shell"，但执行发生在 VM 里；同时提供 `run_python` / `run_node` / `git` 等一等工具，让常见任务不必写 shell | 无 fork/exec（A1） |
| Claude | Hook 执行用户脚本 | **声明式 Hook**：`on: PreToolUse` + `match: tool=write_file, path=**/*.swift` + `action: confirm/protect/notify/log/webhook` | 不能执行下载的代码（A4）；也避免让用户面对脚本调试 |
| Claude | 子代理 = 独立进程/会话 | **进程内 Actor 化子代理**，共享内存预算，可被系统回收并从检查点复活 | 内存与生命周期（A6/A3） |
| DSH | Job 常驻后台推进 | **Job = 检查点状态机**，唤醒时续跑；长等待步骤显式声明为"可挂起点" | 后台时间极短（A3） |
| DSH | 记忆库（服务端） | **全本地 SQLite + FTS5 + sqlite-vec**；知识页由端侧或廉价模型生成 | 隐私与离线（铁律 1） |
| Codex | Responses API reasoning item 回传 | **Gateway 归一化**：把各家 reasoning/thinking 统一为内部 `ReasoningBlock`，再按目标协议序列化 | 模型无关性 |
| Claude | TodoWrite | **可见进度卡片 + 通知**，并允许用户直接改 todo | 手机用户不看终端 |
| 全部 | TUI/文本流 | **卡片化 + Diff 手势审阅 + 语音** | A8 |

### 6.3 明确否决（Reject）

| 被否决的做法 | 出处 | 否决理由 |
|---|---|---|
| 把宿主 shell 直接暴露给模型 | Claude Bash、Codex shell | 手机上无 shell 可暴露；且这是最大攻击面 |
| 下载并动态执行插件/二进制 | 多数桌面 Agent 的插件机制 | App Store 2.5.2；且破坏可审计性 |
| 依赖云端执行 | 所有云端手机 Agent | 违背铁律 1 |
| 用 prompt 里写"不要执行恶意指令"来防注入 | 普遍做法 | 已被反复证伪，必须靠**结构化隔离 + 能力令牌**（见 [09](09-安全与隐私威胁模型.md)） |
| 让模型自由生成 shell 管道处理大文件 | 桌面 Agent 常见 | 手机内存吃不下；必须走流式原语工具（A6） |
| 一次 Turn 无限工具调用 | 全部 | 手机电量与成本不可接受；必须有预算与熔断（见 [10](10-后台执行与可靠性.md) §6） |
| 单一模型深度绑定（含私有推理语义） | Codex/Claude/DSH 各自 | Rune 必须"换模型能力不塌" |

## 8. 冲突裁决规则

三家做法冲突时，按以下优先级裁决（本规则写入工程规范，避免后续反复争论）：

1. **安全 > 能力**：任何"更方便但更宽权限"的默认值一律否决。
2. **可恢复 > 高性能**：宁可慢一点，也要保证随时可断、可续、可回滚。
3. **端侧 > 云端**：能本地做的绝不外发（含小模型能做的推理）。
4. **模型无关 > 单模型最优**：为了在某一家模型上多拿 5% 效果而写死协议语义的一律否决。
5. **少而清晰的工具 > 多而杂的工具**：新增工具必须证明"现有工具组合做不到"。
6. **用户可解释 > 自动化程度**：宁可让用户点一下确认，也不要让 Agent 做了但说不清。
7. **移动原生 > 桌面复刻**：任何"桌面怎么做的我们照抄"的方案，都必须在移动端重新评估一遍交互。

## 9. 反模式清单（写代码前先读这一节）

| 反模式 | 后果 | 正确做法 |
|---|---|---|
| 把 Agent 循环写在 SwiftUI View 里 | 后台被杀、状态错乱、无法测试 | Core 层 Actor，UI 只订阅事件流 |
| 工具直接调 `FileManager.default` | 绕过 VFS，破坏沙箱与回滚 | 一切文件操作必须经 `VFS` 协议 |
| 用 UserDefaults 存会话 | 数据量爆炸、无事务、无查询 | SQLite + WAL |
| 把整个模型响应先攒完再解析 | 手机内存 + 首字延迟灾难 | 全程流式，增量解析 |
| 一次 Turn 里串行调用 20 个工具 | 电量与等待时长不可接受 | 独立工具并行扇出 + 预算控制 |
| 审批弹窗做成模态对话框 | 打断体验，用户会无脑点允许 | 非阻塞审批卡 + 批量授权 + 记住选择 |
| 把"用了哪个模型"藏起来 | 用户无法解释成本与质量差异 | 每个 Turn 标注模型、渠道、成本 |
| 依赖"模型会听话"来防注入 | 安全模型崩塌 | 结构化隔离 + 能力令牌 + 出口白名单 |
